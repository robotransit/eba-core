## Memory Retrieval (PR4)
- [x] ADR-026: Retrieval Semantics & Contract
- [x] ADR-027: Enable/Disable Semantics for Memory Retrieval
- [x] ADR-028: Retrieval Influence Semantics
- [x] ADR-029: Observability & Logging for Retrieval
- [x] ADR-030: Test & Invariant Lock for Memory Retrieval
- [x] Implementation: eck/memory.py
- [x] Tests: tests/test_memory.py
- Invariants enforced (complete):
  - advisory-only (no control authority)
  - read-only context (no mutation or side-effects)
  - disabled = zero retrieval activity (no execution, no logging, no integration)
  - prompt equivalence preserved:
    - disabled ≡ enabled-empty ≡ no-context baseline (no memory block inserted)
  - enabled-empty ≡ no context (returns `None`, no prompt impact)
  - deterministic observability:
    - exactly one log entry per enabled attempt
    - zero log entries when disabled
    - metadata-only logging (no timestamps, no nondeterministic fields)
  - canonical deterministic formatting:
    - fixed sentinels and structure
    - stable, order-preserving (newest-first)
    - reproducible byte-for-byte output
    - single-line normalized fields
    - strict UTC timestamp formatting (`YYYY-MM-DDTHH:MM:SSZ`)
- Status: COMPLETE (canonical formatting implemented; invariant completeness verified via tests; all PR4 requirements satisfied)

## Summary
v0.2.0 builds a deterministic core with explicit policy gate mediation as the control seam. Confidence (PR1), Policy Gate (PR2), and Agent Loop Integration (PR3) form the foundation; memory and similarity follow as advisory layers. PR8 completes the epistemic control loop by reconciling all kernel components to ADR specification, wiring confidence end-to-end, and closing the partial outcome gap via PartialStructure derivation.
