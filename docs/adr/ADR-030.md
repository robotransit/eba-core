# ADR-030: Test & Invariant Lock for Memory Retrieval

**Status**  
Locked (semantic invariant for v0.2.0 core)

## Objective

Define the mandatory, deterministic test surface and invariant-locking requirements for the memory retrieval subsystem in ECK, ensuring that all core semantics from ADR-026 (Retrieval Semantics & Contract), ADR-027 (Enable/Disable Semantics), ADR-028 (Retrieval Influence Semantics), and ADR-029 (Observability & Logging) are verifiably enforced through repeatable, non-flaky tests.

This ADR is strictly scoped to A2.5 and completes the A2 design phase by establishing the test contract — without introducing new behavioral rules, reopening prior ADRs, adding implementation code, or coupling testing to confidence, policy modes, breadth, gating, or execution outcomes.

## Decisions

1. **Test Categories Required**  
   The following categories must be covered with deterministic, isolated unit/integration tests:  
   - Disabled mode isolation (no retrieval calls, no context injection, prompt equivalence)  
   - Enabled-with-empty equivalence (prompt identity to disabled case)  
   - Structural separability of injected memory section (no blending with system/task prompts)  
   - Advisory-only influence (no delegation of generation to memory content)  
   - Read-only boundary (immutability of returned `TaskRecord` items, no mutation pathways)  
   - Deterministic formatting & ordering (stable/version-locked rule applied consistently)  
   - Logging completeness & correctness (structured fields, types, event presence, no sensitive data)  
   - Logger name invariant ("eck-core" used exclusively)  
   - No behavioral coupling (retrieval/logging changes do not affect confidence, policy, breadth, gating)

2. **Testable Conditions (Non-Exhaustive)**  
   Tests must verify the following observable invariants:  
   - Bit-for-bit prompt identity between disabled, enabled-with-empty, and canonical no-context forms (including whitespace, delimiters, section boundaries)  
   - Zero retrieval subsystem interactions (calls, queries, index accesses) when disabled  
   - Exact match of logged fields to declared types and values (`enabled`: bool, `item_count`/`context_length`: non-negative int)  
   - No leakage of `TaskRecord` internal content into logs (only aggregate metadata permitted)  
   - Graceful degradation on logger unavailability (no halt, no visible exceptions in agent loop, no policy change)  
   - Structural separation under simulated tokenization variance (e.g., delimiters remain distinct even in edge token splits)

3. **Test Properties**  
   All tests must be:  
   - Deterministic (no randomness, no real LLMs unless stubbed/mocked)  
   - Isolated (mock retrieval, mock logger, mock prediction callable)  
   - Fast (unit-level preferred; integration only where necessary)  
   - Self-documenting (clear assertions tied to specific invariants)  
   - Coverage-enforcing (100% branch coverage on retrieval toggle, formatting, logging paths)

## Invariants

- All A2.x semantics (026–029) are covered by at least one deterministic test that fails if violated.  
- Prompt equivalence (disabled ≡ enabled+empty ≡ no-context) is tested byte-for-byte, including all delimiters and whitespace.  
- Disabled mode produces zero retrieval subsystem interactions — verifiable via call counting or path tracing.  
- Injected memory section remains structurally separable — testable via delimiter presence and non-blending assertions.  
- Logging produces exactly one structured entry per retrieval attempt with correct types and values.  
- No test introduces behavioral side-effects into the core agent loop (e.g., no real LLM calls unless explicitly stubbed).  
- Tests use the canonical logger name "eck-core" and verify its exclusive use.  
- A1 confidence semantics, policy modes, breadth, and gating remain untouched by retrieval tests.  
- All prior ADRs (026–029) remain closed; no reinterpretation occurs in test assertions.

## Must Never Happen

- Any A2.x invariant (from ADR-026–029) lacking a corresponding deterministic test.  
- Tests relying on non-deterministic elements (real LLM outputs, network, timing assumptions).  
- Tests that mutate shared state or leak side-effects between cases.  
- Assertions that indirectly reopen A1 confidence semantics or couple retrieval to policy/gating.  
- Logging of sensitive `TaskRecord` fields in test setups or assertions.  
- Tests that pass when structural separation is violated or prompt drift occurs.  
- Use of any logger other than "eck-core" in test harnesses.  
- Reopening or reinterpretation of ADR-026–029 decisions or §19 red lines via test logic.
