# ADR-022: Failure vs Non-Failure Classification

**Status**  
Locked (semantic invariant for v0.2.0 core)

## Decision

Classification of critic outcomes is **categorical and primary**.

Severity scales the magnitude of confidence delta **within** the category (larger downward pull for higher severity) but **never** reclassifies the category.

## Core classification taxonomy (hard invariants for v0.2.0)

- **Failure**  
  - **Triggered by:** critic outcome explicitly categorized as failure per critic contract.  
  - **Epistemic meaning:** the attempt violated core constraints or produced an invalid/unacceptable result.  
  - **Confidence implications:**  
    - Triggers downward pressure (pull toward lower confidence).  
    - Triggers monotonic clamp — no upward movement permitted in the next cycle (failure window).  
    - May contribute to streak/drift escalation (e.g. consecutive failures → policy mode tightening).  
  - **Never** produced by severity alone.

- **Success**  
  - **Triggered by:** critic outcome explicitly categorized as success per critic contract.  
  - **Epistemic meaning:** the attempt met all required constraints and produced an acceptable result.  
  - **Confidence implications:**  
    - Allows upward movement (pull toward higher confidence).  
    - No monotonic clamp (recovery window open).  
    - Resets or weakens negative streaks.

- **Partial**  
  - **Triggered by:** critic outcome explicitly categorized as partial per critic contract (neither full success nor outright failure).  
  - **Epistemic meaning:** partial epistemic validity — evidence of progress but with caveats.  
  - **Confidence implications:**  
    - Neutral to downward pressure (depending on severity).  
    - No monotonic clamp (upward movement still possible).  
    - Does not trigger failure window or hard escalation.

- **Rejected / Deferred**  
  - **Triggered by:** explicit rejection by policy (e.g. should_execute returned False) or deferral before execution/critic.  
  - **Epistemic meaning:** no new evidence produced (no outcome to evaluate).  
  - **Confidence implications:**  
    - No update (per ADR-021 no-critic rule).  
    - No monotonic clamp.  
    - No direct contribution to confidence dynamics.  
  - (Any downstream effect of repeated deferral belongs in policy logic or drift, not confidence updates.)

- **Cross-validation disagreement**  
  - Maps to: severity = 1.0 (maximal penalty within category).  
  - Category preserved — disagreement does **not** upgrade partial/rejected to failure.  
  - Example: partial + disagreement → partial with severity=1.0 (strong downward within partial category).

## Severity role (explicit boundary)

- Severity ∈ [0, 1] scales the magnitude of confidence delta **within the category** (larger downward pull for higher severity).  
- Higher severity → larger downward pull (even within success/partial categories).  
- Must **never** reclassify category (no severity threshold turns partial → failure).  
- Failure category already implies strong downward + monotonic clamp — severity further amplifies magnitude **within** that category.

## Rationale

- Preserves critic authority: critic decides what kind of outcome occurred; confidence logic decides how strongly to react.  
- Enables clean asymmetry/monotonicity: failure category provides hard semantic trigger for clamp; severity provides tuneable gradient inside categories.  
- Maintains epistemic clarity: “failure” remains a meaningful event (“constraints violated”), not a tuning artifact.  
- Avoids brittleness: tests stay stable across severity tuning changes.  
- Aligns with refusal-over-fabrication posture: categorical failure forces strong conservative response.

## Consequences

### Positive

- Deterministic monotonicity by category (easy to test/enforce).  
- Explainable logs: “failure category → monotonic clamp applied” vs “partial high-severity → strong downward nudge”.  
- Clear separation of concerns: critic owns semantics, confidence owns dynamics.  
- Future-proof: adding new outcome categories (e.g. “ambiguous”) slots in cleanly.

### Trade-offs

- Tuning flexibility slightly reduced (cannot make high-severity partial behave exactly like failure without changing critic).  
- Acceptable, because category integrity > tuning convenience.

## Must never happen (red lines)

- Severity alone reclassifies partial / rejected / deferred → failure.  
- Cross-validation disagreement upgrades or alters outcome category (it always maps to severity = 1.0 within the original category).  
- Any logic that makes “failure” an emergent numeric property rather than categorical.  
- Monotonic clamp applied outside failure category.  
- Confidence movement that ignores category (e.g. treating all high-severity outcomes identically regardless of success/partial/failure).

## Tests required (high-level deterministic assertions)

- Critic explicit success category → upward allowed, no clamp.  
- Critic explicit failure category → downward + monotonic clamp next cycle.  
- Partial outcome + severity=1.0 → partial category, strong downward, no monotonic clamp.  
- Rejected/deferred cycle → confidence unchanged (assert == previous value), no monotonic clamp, no streak contribution.  
- Cross-validation disagreement → severity=1.0, category unchanged (e.g. partial remains partial).  
- Deterministic replay: failure → next cycle upward blocked even if success occurs; partial high-severity → next cycle upward still possible.
