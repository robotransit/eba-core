# ADR-036: Test Coverage & Invariant Enforcement Metrics

**Status**  
LOCKED (semantic invariant for v0.2.0 core)

## Objective

Define precise, enforceable test coverage thresholds, per-module goals, enforcement rules, and reporting standards for the CI workflow established in ADR-034 and implemented in ADR-035.  

This ADR locks the quantitative and qualitative metrics that ensure the deterministic core layer verifies all critical invariants with high confidence, while maintaining the microkernel's verifiability path and preventing coverage regression.

This ADR is scoped to the third ("if needed") step of A5 in the v0.2.0 roadmap (ADR-020). It builds directly on ADR-034 (foundational contract) and ADR-035 (workflow implementation) without reopening their decisions, emergent architectural properties (especially Properties 1, 11, 12), §19 red lines, or prior locked ADRs.

## Decisions

1. **Overall Coverage Thresholds**  
   - Branch coverage target (core layer only): ≥ 95% overall  
   - Failure enforcement: CI fails if branch coverage < 95% (measured via `pytest-cov --cov-fail-under`)  
   - **Rationale:** 95% ensures near-complete exercise of deterministic paths while allowing minor exclusions (e.g., unreachable error handling).

2. **Per-Module / Critical-Path Goals**  
   - Core kernel modules (must achieve 98–100% branch coverage):  
     - `eck/agent.py` (orchestration, step cycle, lifecycle transitions)  
     - `eck/critic.py` (parsing, pessimistic failure, severity mapping)  
     - `eck/memory.py` (WorldModel append-only, retrieval toggle equivalence)  
     - `eck/queue.py` (TaskQueue deterministic ordering, bounded behavior)  
     - `eck/config.py` (PolicyMode, immutable logger, config surface)  
   - Guardrail-specific paths (from ADR-033): 100% branch coverage required  
     - Adversarial structured field mocks  
     - Prompt removal / toggle equivalence assertions  
     - No-leakage tests (kernel ignores parsed control fields)  
   - Future critical kernel modules **MUST** default to ≥98% branch coverage; any exception requires a new ADR justifying lower coverage.  
   - **Exclusions allowed** (0% coverage acceptable):  
     - `tests/` directory  
     - `examples/` directory  
     - `docs/` and non-code files

3. **Enforcement Mechanism**  
   - Core layer only: `pytest-cov --cov-fail-under=95` (overall) and per-file thresholds enforced via pytest-cov plugin configuration (e.g., coverage thresholds per module via `pyproject.toml` or pytest-coverage extension) or a small post-run Python script that parses `coverage.xml` and fails CI if thresholds are violated.  
     pytest-cov plugin configuration is preferred for simplicity; post-run script is used only as fallback.  
     The chosen enforcement method (plugin vs script) **MUST** be documented in `CONTRIBUTING.md` or `README` for maintainer clarity.  
   - CI failure: if any threshold violated → `core-tests` job fails → PR/merge blocked.  
   - Coverage delta check: optional PR comment showing coverage change (via Codecov or diff tool) — delta comments **MUST NOT** influence CI pass/fail status (purely informational).  
   - No threshold lowering permitted without new ADR.

4. **Reporting & Auditing Standards**  
   - **Required artifacts** (uploaded on every core run):  
     - `coverage.xml` (for Codecov or similar)  
     - `htmlcov/` directory (human-readable report)  
     - `junit.xml` (test results for CI summary)  
   - Coverage artifacts **SHOULD** be linked to eck-core logger artifacts (per ADR-034/035) for end-to-end traceability, especially on guardrail tests.  
   - **Optional:** coverage trend tracking (e.g., per-module % over time, retained for last 30 runs) for early detection of subtle regressions in kernel paths; regression alerts/notifications can be surfaced via Codecov PR comments or Slack if configured (e.g., >2% drop triggers notification).  
   - **Optional:** Codecov integration (core coverage badge in README, PR status check, comment with diff).  
   - Core layer **MUST NOT** include capability/extras coverage in enforcement (independence preserved).  
   - Audit requirement: maintainers **MUST** review coverage report before merging major kernel changes.

## Rationale & Architectural Alignment

- High coverage on kernel paths protects TCB containment (Property 1) and formal-verifiability path (Property 12) by exercising nearly all deterministic branches.  
- 100% on guardrail paths enforces ADR-033 invariants (no authority leakage) with zero tolerance for gaps.  
- Per-module goals ensure uniform protection rather than overall average hiding weak spots.  
- Enforcement via `--cov-fail-under` preserves atomic fallback (Property 4) in CI itself: coverage regression blocks merge.  
- Reporting supports observability before enforcement (Property 5) — failures are visible and auditable.

## Must Never Happen (Red Lines)

- Coverage enforcement disabled, ignored, or thresholds lowered without new ADR.  
- Fake coverage techniques (e.g., excessive `# pragma: no cover`, test skipping critical paths).  
- Inclusion of capability/extras coverage in core enforcement metrics.  
- CI passing with <95% overall branch coverage or <98% on kernel modules.  
- Coverage reports omitting guardrail-specific paths (ADR-033 adversarial tests).  
- Reopening of ADR-034, ADR-035, or prior ADRs via coverage configuration.
