# ADR-029: Observability & Logging for Retrieval

**Status**  
Locked (semantic invariant for v0.2.0 core)

## Objective

Define the minimal, deterministic observability and logging contract for memory retrieval operations in ECK, ensuring that all relevant retrieval events, states, and outcomes are auditable without introducing behavioral side-effects, authority surfaces, or coupling to other subsystems.

This ADR is strictly scoped to A2.4 and builds directly on the retrieval contract (ADR-026), enable/disable semantics (ADR-027), and influence semantics (ADR-028), without reopening prior decisions, expanding scope into A2.5 testing, or coupling logging to confidence, policy modes, breadth, gating, or execution behavior.

## Decisions

1. **Logged Retrieval Events**  
   The following retrieval-related events must be logged using the canonical logger ("eck-core"):  
   - Every retrieval attempt (whether enabled or disabled).  
   - The effective state of the enable/disable toggle at the time of the attempt.  
   - The number of items returned (0 or positive integer).  
   - The length (in tokens or characters) of the formatted/injected memory context block (0 if no context).

2. **Log Structure and Consistency**  
   Logs must be emitted at INFO level (or equivalent observability tier) with structured key-value fields for machine-readability, including at minimum:  
   - `event_type`: e.g., "memory_retrieval_attempt", "memory_context_injected"  
   - `enabled`: boolean (true/false)  
   - `item_count`: integer  
   - `context_length`: integer (0 if empty or disabled)  
   - `agent_id` or `run_id` (if applicable for correlation)  
   No free-form or unstructured log messages are permitted for these events; all relevant data must appear in structured fields.

3. **No Behavioral Coupling**  
   Logging is strictly side-effect free:  
   - Log emission does not alter retrieval behavior, prompt generation, confidence, policy, or execution paths.  
   - Logging failures (e.g., logger unavailable) must not halt execution, throw exceptions visible to the agent loop, or trigger HALT.  
   - In case of logger unavailability, the system must gracefully degrade by skipping the log entry without affecting core execution, prompt generation, or policy behavior.  
   - Fallback mechanisms (e.g., stderr, in-memory buffer) are implementation-specific and outside this contract.

## Invariants

- All retrieval attempts (enabled or disabled) produce exactly one corresponding log entry with the required structured fields.  
- When disabled: `item_count` = 0, `context_length` = 0, and no retrieval subsystem is invoked (consistent with ADR-027).  
- When enabled but empty: `item_count` = 0, `context_length` = 0, and the log reflects the no-context outcome.  
- When context is injected: `context_length` > 0 and accurately reflects the serialized block length from ADR-026 formatting.  
- Logging uses exclusively the immutable logger name "eck-core" (per global invariant).  
- Log emission introduces no new authority surfaces, no coupling to confidence scoring, policy mode transitions, task breadth, gating, or any behavioral control.  
- Observability remains read-only and advisory: logs provide visibility into retrieval but do not influence generation, prediction, or execution.  
- All structured fields must conform to their declared types (`enabled`: boolean, `item_count`/`context_length`: non-negative integer); type-correctness is part of the observability contract.  
- A1 confidence semantics, ADR-026/027/028 contracts remain closed and unaffected.

## Must Never Happen

- Omission of a log entry for any retrieval attempt (enabled or disabled).  
- Logging of unstructured or free-form messages for retrieval events (structured fields only).  
- Logging of sensitive/internal `TaskRecord` content (e.g., full objective/prediction/feedback) — only aggregate metadata (count, length) is permitted.  
- Log emission altering prompt form, generation output, confidence, policy, breadth, or gating behavior.  
- Runtime exceptions from logging propagating to the agent loop or triggering HALT.  
- Use of any logger name other than "eck-core".  
- Coupling of logging presence/volume to behavioral decisions (e.g., no conditional logic based on log success).  
- Reopening or reinterpretation of ADR-026, ADR-027, ADR-028, A1 semantics, or §19 red lines.
