# ADR-033: Prompts Integration Cleanup & Authority Guardrails

**Status**  
LOCKED (semantic invariant for v0.2.0 core)

## Objective

Finalize the disposition of `PRIORITIZATION_PROMPT` and any related or analogous prompts (including `GOAL_ACHIEVED_PROMPT`), eliminate unused or weakly justified prompt surface area, and establish binding guardrails that prevent any form of prompt-derived authority leakage — direct, indirect, or via structured control fields — into kernel governance decisions.

This ADR is scoped to A4 in the v0.2.0 roadmap (ADR-020). It builds on the emergent architectural properties document, §19 red lines, A2 memory wiring contracts (ADR-026–030), and prior prompt analyses without reopening locked semantics from A1–A3.

## Decisions

1. **PRIORITIZATION_PROMPT**  
   - **Disposition:** DELETE (full removal from codebase and documentation; already absent in current repository state)  
   - **Rationale:** Would have influenced task queue ordering → constitutes behavioral governance decision → violates one-way authority gradient (Property 2), enlarges effective TCB (Property 1), and introduces nondeterministic upstream effects into deterministic prompt boundary (Property 3).  
   - **Replacement:** Not required. Current `TaskQueue` implementation uses deterministic bounded ordering (likely FIFO or equivalent reverse-chronological/metadata-based selection) with no LLM or prompt involvement observed.

2. **GOAL_ACHIEVED_PROMPT**  
   - **Disposition:** OMIT / DELETE (not present or discoverable in the current codebase; no usage — advisory or direct — identified in critic, task lifecycle, or related logic)  
   - **Rationale:** Absent in repository; no evidence of structured goal-completion fields or prompt-driven lifecycle influence. Kernel already owns completion judgments via deterministic predicates (critic category/severity, task metadata, success criteria).  
   - **If analogous goal-reflection logic is desired in future:** implement only as pure advisory critic output (logged, memory-injected, non-authoritative); kernel retains exclusive control over transitions.

3. **Binding Guardrail: No Structured Control Fields from Prompts**  
   Kernel governance decisions (task lifecycle transitions, goal completion, queue pruning, policy mode upgrades, execution halting, confidence overrides, breadth changes, etc.) **MUST NOT** be influenced by structured fields, JSON-like outputs, or any control signals parsed from LLM-generated text (including prompt responses, critic outputs, or memory-injected content).  
   All such decisions remain exclusively under deterministic kernel predicates and invariants.  
   Any future prompt that might emit structured data is advisory-only; kernel logic **MUST** ignore or explicitly reject governance-relevant fields.

## Invariants

- No prompt literal (including deleted/omitted ones) influences kernel governance decisions.  
- `TaskQueue` ordering and task selection remain deterministic and prompt-independent.  
- Task lifecycle transitions (completion, deferral, failure handling, etc.) are governed solely by critic category/severity and deterministic predicates — never by LLM claims or structured fields.  
- No structured control leakage: fields such as `{"goal_achieved": true/false}`, `{"priority": "..."}`, `{"halt": true}`, etc. parsed from prompt/critic/memory output have zero effect on kernel behavior when predicates are fixed.  
- All prompt removals/omissions preserve byte-for-byte prompt equivalence under toggle/disabled/fallback conditions (per A2 contracts).  
- A1 confidence semantics, A2 memory wiring (ADR-026–030), ADR-031/032 similarity contracts, and §19 red lines remain closed and unaffected.

## Must Never Happen

- Retention or reintroduction of prompts that create latent control channels without atomic fallback to deterministic baseline.  
- Future prompt additions treated as API surface or literal-string contracts.  
- Kernel deferring to LLM-generated structured fields for lifecycle, queue, policy, confidence, breadth, or halt decisions.  
- Prompt-derived authority leakage (direct parsing or indirect influence) into any kernel governance surface.  
- Behavioral divergence after prompt cleanup (queue order, task states, confidence trajectory, policy mode must remain identical).  
- Tests passing when structured control fields from prompts affect kernel decisions.  
- Reopening of A1 confidence semantics, A2 memory wiring, or §19 red lines.

## Tests Required (High-Level Deterministic Assertions)

- **PRIORITIZATION_PROMPT removal / queue ordering:** task selection from `TaskQueue` remains deterministic (FIFO or current baseline order) and unchanged after any prompt-related cleanup; no LLM influence path exists.  
- **GOAL_ACHIEVED_PROMPT absence:** no structured goal fields influence lifecycle; adversarial insertion of `{"goal_achieved": true/false}` in mocked critic output has zero effect on kernel transitions when predicates fixed.  
- **No Structured Control Field Leakage (Core Guardrail):**  
  Mock prompt/critic output emitting governance-relevant fields (e.g. `{"goal_achieved": true}`, `{"priority": "high"}`, `{"halt": true}`).  
  Parse in test harness simulating kernel.  
  Assert: lifecycle transitions, queue selection, policy mode, execution continuation, confidence updates identical to adversarial case (false/low/omitted).  
- **Prompt Removal / Toggle Equivalence:**  
  Replace any hypothetical prompt output with fixed/adversarial value → assert identical kernel behavior (task states, queue, policy, confidence trajectory) when kernel predicates fixed.  
- **End-to-End Lifecycle Replay:**  
  Fixed critic outcome sequence + mocked prompt outputs (including structured fields) → identical final agent run state (queue empty?, final confidence?, policy mode?, halted?) regardless of prompt content.  
- **Negative Control — Adversarial Prompt:**  
  Force misleading structured fields (e.g. `{"goal_achieved": false}` when kernel criteria met) → kernel still completes task if deterministic criteria satisfied (no deference to LLM claim).  
- **Prompt Equivalence:** disabled/removed prompts produce identical prompt forms to baseline (byte-for-byte, including delimiters/whitespace).  
- All tests **MUST** use the immutable logger "eck-core" and assert no unexpected structured log entries that would indicate coupling.
