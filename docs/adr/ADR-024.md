# ADR-024: Minimal Input Signal Set for Confidence Update

**Status**  
Locked (semantic invariant for v0.2.0 core)

## Decision

Confidence updates are driven by a **whitelist** of admissible input signals.  
The set is divided into **mandatory** (always present) and **optional** (configurable, additive-only) signals.  
This ADR defines only **admissibility** (which signals are allowed to influence confidence at all) and **directional permissions** (which directions each signal may push when active).  
No weighting, aggregation, history depth, or net direction logic is defined here.

## Canonical signal set (hard invariants for v0.2.0)

### Mandatory inputs (always active, cannot be disabled)

- **Critic outcome category**  
  - **Source:** `critic.evaluate()` → explicit category (failure / success / partial / rejected/deferred)  
  - **Directional permissions** (gates from ADR-023):  
    - Failure → downward permitted + triggers failure window (upward forbidden next cycle)  
    - Success → upward permitted (unless inside failure window) + downward permitted  
    - Partial → upward permitted + downward permitted  
    - Rejected/deferred → no movement permitted  
  - **Role:** primary epistemic evidence; defines the permission gates.

- **Critic severity**  
  - **Source:** `critic.evaluate()` → severity ∈ [0, 1]  
  - **Directional permissions:** Amplifies downward movement only (when downward is permitted by category)  
  - Never enables upward movement  
  - Never overrides or reclassifies category  
  - **Role:** modulates magnitude within allowed directions.

### Optional inputs (configurable via ECKConfig; disabled by default or via toggle; additive only)

- **DriftMonitor signals** (e.g. streak, severe flag, perceptual z-score)  
  - **Directional permissions:** downward only (amplifies caution).  
  - Never enables upward movement.  
  - Never overrides critic category or gates.

- **Feasibility checks / prediction-derived signals** (e.g. numeric feasibility bias from prediction phase)  
  - **Directional permissions:** downward only (signals potential instability).  
  - Never enables upward movement.  
  - Never overrides critic category or gates.

- **Memory-derived aggregates** (future; e.g. similarity-weighted past outcomes)  
  - **Directional permissions:** downward only (negative memory bias).  
  - Never enables upward movement.  
  - Never overrides critic category or gates.

## Configurability guarantees

- Optional signals can be fully disabled without invalidating core confidence semantics (update still occurs using mandatory critic inputs only).  
- When disabled: no influence on confidence (no phantom downward pull).  
- Enabling an optional signal adds only downward amplification where permitted by category gates.

## Rationale

- Preserves epistemic purity: confidence remains fundamentally driven by observed outcomes (critic), not internal predictions or historical aggregates.  
- Enforces layering invariants: prediction/memory/DriftMonitor provide advisory caution signals only; critic owns primary epistemic authority.  
- Enables safe experimentation: optional signals can be toggled without regressing core behavior or breaking deterministic tests.  
- Aligns with refusal-over-fabrication: upward movement requires positive critic evidence; optional signals can only discourage, never encourage.  
- Keeps design modular: mechanics ADRs (aggregation, weighting) can build on a fixed, small input surface.

## Consequences

### Positive

- Deterministic baseline behavior (critic-only mode is always valid and explainable).  
- Clear audit trail: logs can distinguish “critic-driven” vs “drift-augmented” downward pressure.  
- Easy test isolation: core semantics testable with optional signals disabled.  
- Future-proof: new optional signals (e.g. external risk scores) slot in as downward-only without redesign.

### Trade-offs

- Upward movement relies exclusively on critic success/partial (no optional signal can accelerate recovery).  
- Acceptable, because epistemic justification for trust must come from observed outcomes, not internal signals.

## Must never happen (red lines)

- Any non-critic signal becoming mandatory or non-disableable.  
- Optional signal enabling upward movement on its own (e.g. positive drift allowing recovery without critic success).  
- Optional signal overriding or reclassifying critic category/gates.  
- Confidence update occurring without critic inputs (even if optionals are enabled).  
- Phantom influence when optional signals are disabled (must be zero effect).

## Tests required (high-level deterministic assertions)

- Critic-only mode (all optionals disabled): update occurs solely based on category + severity; upward only on success/partial, downward amplified by severity, failure window enforced.  
- Enable DriftMonitor signals → additional downward amplification on failure/partial (where permitted), no upward created, no category change.  
- Enable feasibility signals → similar downward-only effect, no upward, no override.  
- Disable all optionals after enabling → behavior reverts exactly to critic-only (assert == previous critic-only value trajectory).  
- Deterministic replay: failure + high severity + drift enabled → strong downward + window; next cycle success with drift disabled → upward permitted (window expired).  
- Rejected/deferred critic outcome → no update even with optionals enabled.
