# ADR-025: Confidence Update Mechanics (EWMA)

**Status**  
Locked (semantic invariant for v0.2.0 core)

## Decision

The rolling confidence signal is updated using an event-driven, delta-based **Exponentially Weighted Moving Average (EWMA)**, applied once per cycle that produces a critic outcome.

Confidence semantics are driven by accumulated evidence deltas derived from observed outcomes. EWMA is used solely as a smoothing operator over permitted deltas, not as a mechanism for convergence toward semantic attractors.

The canonical update form is:

"inverted commas three backticks"
delta_smoothed = EWMA(delta_raw)
confidence_new = confidence_old + delta_smoothed
"inverted commas three backticks"

Where:
- confidence_old ∈ [0,1] is the value from the previous update (initial value = 0.5).
- delta_raw is the signed evidence delta implied by the current cycle’s outcome.
- delta_smoothed is the EWMA-smoothed delta.
- α ∈ (0,1] is the smoothing factor (higher α = faster adaptation to recent evidence).

EWMA is applied only on cycles with a critic outcome. There is no time-based decay, leak, relaxation, or drift on non-update cycles.

## Update Sequence (Strict Order)

- Compute raw evidence delta (delta_raw)  
  Derived solely from the current cycle’s critic outcome category and severity (mandatory inputs), plus any enabled optional downward-only signals.

- Enforce directional permission gates (ADR-023)  
  - If upward movement is forbidden (active failure window) and delta_raw > 0 → clamp delta_raw = 0.  
  - If downward movement is forbidden (only possible for rejected/deferred, which produce no update) → no action needed.

- Apply EWMA smoothing  
  - delta_smoothed = EWMA(delta_raw) using fixed α.

- Apply bounded accumulation  
  - confidence_new = clamp(confidence_old + delta_smoothed, 0.0, 1.0).

The clamped value becomes the final confidence for the cycle.

## Evidence Delta Semantics (No Numerics)

### Mandatory inputs

- **Success** category → positive delta (typically small), upward permitted unless gated.
- **Failure** category → negative delta (typically large), downward permitted; triggers failure window.
- **Partial** category → small positive or negative delta depending on severity; both directions permitted.
- **Rejected / Deferred** → no update (no delta; confidence unchanged).

### Severity

- Scales the magnitude of negative deltas only (when downward is permitted).
- Never enables upward movement.
- Never flips or overrides category gates.

### Optional signals (when enabled)

- Downward-only amplification of negative deltas.
- Never produce upward deltas.
- Never override critic category or gates.

## Observability & Logging Expectations

Every update must be logged via logger "eck-core" with at least:
- timestamp
- cycle ID (task cycle identifier)
- prior confidence
- critic outcome category
- critic severity
- enabled optional signals (names/values, if any)
- raw evidence delta
- any gate clamp applied (with reason, e.g., "failure window active")
- EWMA-smoothed delta
- final clamped confidence
- brief causal attribution (e.g., "downward delta from failure + severity=0.9")

Logs must support deterministic replay: given the log sequence and fixed α, the confidence trajectory is exactly reproducible.

## Rationale

- Epistemic integrity: confidence moves only on observed evidence; no evidence-free motion.
- Clarity: deltas make causality explicit.
- Asymmetry & monotonicity: enforced by gates before smoothing.
- Minimal state: single scalar confidence + fixed α.
- Observability: deltas and clamps are auditable and replayable.

## Consequences

### Positive

- Deterministic, replayable trajectories from fixed inputs.
- Earned recovery after failure windows; no semantic jumps.
- Clean integration with optional downward-only signals.

### Trade-offs

- No automatic forgetting on idle cycles (intentional).
- Recovery speed governed by α and evidence frequency (tunable later).

## Must never happen (red lines)

- Any confidence movement on cycles without a critic outcome.
- Any time-based decay, leak, relaxation, or drift on non-update cycles.
- Bypassing or ignoring directional permission gates (ADR-023).
- Optional signals producing upward deltas or reclassifying critic outcomes.
- Unlogged updates or missing causal attribution.
- Confidence escaping [0,1] at any point.

## Tests required (high-level deterministic assertions)

- Fixed α, outcomes [success, success, failure, success] → two upward moves, sharp drop on failure, next success blocked by failure window, subsequent success allowed.
- Rejected/deferred cycle → confidence unchanged (assert == previous).
- Failure with higher severity → larger negative delta than lower severity.
- Partial with severity=1.0 + optional signal enabled → more negative than partial alone.
- Active failure window + success → positive delta clamped to zero.
- Deterministic replay: identical inputs and α yield identical trajectory.
- All optionals disabled → critic-only behavior remains valid and bounded.
- Optional drift signal enabled → additional downward influence occurs only on permitted update cycles; zero effect on rejected/deferred cycles (assert == critic-only).
