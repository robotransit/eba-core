# ADR-043: Demonstration Policy Module

**Status:** Proposed
**Version:** v0.3.0 (Demonstration Layer)
**Date:** 2026-03-29

---

## Objective

Define a minimal, deterministic **demonstration policy module** that implements the `PolicyGate` contract end-to-end and proves that:

> Epistemic signals (confidence) are translated into execution control exclusively through policy, without leaking authority into any other subsystem.

This module is **not** a production policy system. It is a **reference implementation** that demonstrates correct integration, invariants, and architectural boundaries.

---

## Scope

This ADR defines:

* A deterministic mapping from epistemic signals → `PolicyDecision`
* A concrete implementation of the `PolicyGate` interface
* Explicit handling of all execution modes:

  * `EXECUTE`
  * `RETRY`
  * `DEGRADE`
  * `HALT`
* Proper use of `PolicyContext`, including `failure_window_active`

This ADR does **not** define:

* Learning or adaptive policies
* Dynamic rule generation
* Integration with memory, prompts, or execution internals
* Any extension of authority beyond the policy layer

---

## Design Principles

### 1. Deterministic and Pure

The policy module must be:

* Deterministic: identical inputs → identical outputs
* Pure: no side effects, no external calls, no hidden state

---

### 2. Exclusive Consumer of Epistemic Signals

The policy module is the **only component** that may interpret:

* `confidence`
* `PolicyContext` (e.g., `failure_window_active`)

No other subsystem may use these signals for behavioral control.

---

### 3. No Execution Authority

The policy module:

* **does not perform actions**
* **does not call execution functions**
* **does not mutate system state**

It only returns a `PolicyDecision`.

---

### 4. Strict Contract Surface

The policy module consumes only:

* `proposed_action`
* `confidence`
* `context: PolicyContext`

And produces only:

* `PolicyDecision`

No additional inputs or outputs are permitted.

---

## Policy Model

### Confidence Thresholds

Define fixed thresholds:

* `T_EXECUTE = 0.7`
* `T_DEGRADE = 0.5`
* `T_RETRY   = 0.3`

These thresholds partition the confidence space:

| Confidence Range | Mode     |
| ---------------- | -------- |
| ≥ 0.7            | EXECUTE* |
| [0.5, 0.7)       | DEGRADE  |
| [0.3, 0.5)       | RETRY    |
| < 0.3            | HALT     |

* Subject to failure window suppression (see below)

---

### Failure Window Adjustment (Explicit Semantics)

If:

* `context.failure_window_active == True`

Then:

* **EXECUTE is disallowed for this cycle**, regardless of confidence
* High-confidence cases (≥ 0.7) are **downgraded to DEGRADE**
* No upward movement into EXECUTE is permitted

This yields the following explicit behavior:

| Condition                                        | Mode    |
| ------------------------------------------------ | ------- |
| confidence ≥ 0.7 AND failure_window_active=False | EXECUTE |
| confidence ≥ 0.7 AND failure_window_active=True  | DEGRADE |

This makes the suppression behavior **deterministic and non-ambiguous**.

---

## Decision Function

Pseudo-definition:

```
if confidence >= T_EXECUTE:
if not failure_window_active:
mode = EXECUTE
else:
mode = DEGRADE
elif confidence >= T_DEGRADE:
mode = DEGRADE
elif confidence >= T_RETRY:
mode = RETRY
else:
mode = HALT
```

## Reference Implementation

### File Location

The demonstration module MUST live in:

```
eck/demo_policy_gate.py
```

Rationale:

* `eck/policy_gate.py` owns the **contract layer**
* `DemoPolicyGate` is a **concrete reference implementation**
* Separation preserves architectural clarity and authority boundaries
* Establishes the correct pattern for future domain-specific policy modules

---

### Class Definition

```
class DemoPolicyGate(PolicyGate):
def evaluate(self, proposed_action, confidence, context):
...
```
---

### Full Behavior

```
def evaluate(self, proposed_action, confidence, context):
if confidence >= 0.7:
if not context.failure_window_active:
return PolicyDecision(
mode=ExecutionMode.EXECUTE,
cause=PolicyCause.CONFIDENCE,
reason="confidence high",
rule_id="RULE_EXECUTE_CONF_HIGH",
)
return PolicyDecision(
mode=ExecutionMode.DEGRADE,
cause=PolicyCause.CONFIDENCE,
reason="failure window active — execute suppressed",
rule_id="RULE_DEGRADE_FAILURE_WINDOW",
)

if confidence >= 0.5:
    return PolicyDecision(
        mode=ExecutionMode.DEGRADE,
        cause=PolicyCause.CONFIDENCE,
        reason="confidence moderate",
        rule_id="RULE_DEGRADE_CONF_MID",
    )

if confidence >= 0.3:
    return PolicyDecision(
        mode=ExecutionMode.RETRY,
        cause=PolicyCause.CONFIDENCE,
        reason="confidence low",
        rule_id="RULE_RETRY_CONF_LOW",
    )

return PolicyDecision(
    mode=ExecutionMode.HALT,
    cause=PolicyCause.CONFIDENCE,
    reason="confidence below minimum threshold",
    rule_id="RULE_HALT_CONF_MIN",
)
```

## Integration

The module integrates via dependency injection:

```
agent = ECKAgent(
objective="...",

)
```

No changes to:

* `agent.py`
* `execution.py`
* `confidence.py`

---

## Invariants

This module must uphold:

### Policy Isolation

* No coupling to memory, execution, or prompt layers

### Determinism

* Same inputs → same `PolicyDecision`

### No Side Effects

* No logging-driven behavior changes
* No mutation of external state

### Authority Boundary

* Policy produces decisions only
* Execution remains strictly downstream

---

## Observability

Policy decisions may be logged, but:

* Logging must not affect behavior
* Logging must not introduce timing or ordering dependencies

---

## Test Requirements

The demonstration module must include explicit tests for:

### Threshold Boundaries

Each threshold MUST be tested with:

* Value exactly at threshold:

  * `confidence = 0.7`, `0.5`, `0.3`
* Value just below threshold:

  * e.g. `0.699`, `0.499`, `0.299`

### Failure Window Suppression

Explicit tests for:

* `confidence ≥ 0.7` with:

  * `failure_window_active=False` → EXECUTE
  * `failure_window_active=True`  → DEGRADE

### Determinism

* Repeated evaluation with identical inputs produces identical outputs

---

## Rationale

This ADR exists to validate the architectural claim:

> Probabilistic cognition is governed by deterministic control.

It demonstrates that:

* Confidence remains epistemic
* Policy is the sole translator to behavior
* Execution authority remains isolated and downstream

---

## Future Extensions

This module may be extended or replaced with:

* Domain-specific policy rules
* Multi-signal policies (still mediated exclusively)
* Configurable thresholds

However, all extensions must preserve:

* Determinism
* Purity
* Authority isolation

---

## Summary

The Demonstration Policy Module:

* Implements the `PolicyGate` contract concretely
* Proves end-to-end control flow correctness
* Maintains strict architectural boundaries
* Serves as a reference for future policy design

This is the first complete realization of the ECK control architecture with:

* Epistemic signal → Policy → Execution boundary fully operational
