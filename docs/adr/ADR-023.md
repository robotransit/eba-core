# ADR-023: Basic Asymmetry & Recovery Shape (Semantics Only)

**Status**  
Locked (semantic invariant for v0.2.0 core)

## Decision

Confidence movement is governed by **permission gates** per outcome category.  
These gates define when upward or downward movement is allowed or suppressed.  
Magnitude and actual sign (if permitted) are determined by later mechanics (severity, EWMA, inputs); this ADR defines **only the gates**.

## Permission rules (hard invariants for v0.2.0)

- **Failure category**  
  - **Downward movement:** always permitted.  
  - **Upward movement:** forbidden during the single-cycle failure window (the immediately next cycle after the failure).  
  - **After the failure window expires:** upward movement permitted (recovery possible).

- **Success category**  
  - **Upward movement:** permitted (unless currently inside a failure window from a prior cycle).  
  - **Downward movement:** permitted (severity may still pull downward even on success).

- **Partial category**  
  - **Upward movement:** permitted.  
  - **Downward movement:** permitted.  
  (Both directions remain open; no automatic suppression.)

- **Rejected / Deferred**  
  - **Upward movement:** forbidden (no update occurs per ADR-021).  
  - **Downward movement:** forbidden (no update occurs per ADR-021).  
  - No movement at all.

- **Severity interaction**  
  - Amplifies downward movement only (when downward is permitted).  
  - Never flips permission rules (cannot suppress upward in partial/success or force upward in failure window).  
  - Never overrides category gates.

- **Recovery after failure**  
  - Success or partial in the cycle immediately after a failure: upward movement remains forbidden (failure window still active).  
  - Success or partial after the failure window expires: upward movement permitted (contributes to recovery).  
  - No automatic reset or acceleration of recovery beyond gate opening.

## Rationale

- Enforces asymmetry by construction: failures create a mandatory conservative pause (one cycle no upward) while still allowing downward pressure.  
- Aligns with epistemic posture: after evidence of violation, trust does not rebound immediately — one full cycle of evidence is required before recovery is semantically allowed.  
- Preserves layering: gates are semantic preconditions; actual deltas are computed downstream (inputs, EWMA).  
- Keeps explainability high: logs can state “upward suppressed due to active failure window from previous cycle” vs vague “low recovery”.  
- Future-proof: single-cycle default is minimal and extensible (longer windows via later ADR).

## Consequences

### Positive

- Deterministic monotonicity enforcement (testable per cycle).  
- Clear causal chains in logs (“upward blocked — failure window active”).  
- Prevents premature optimism after failure without blocking downward caution.  
- Success after window provides clean recovery path.

### Trade-offs

- One-cycle latency on recovery may feel conservative (acceptable given refusal-over-fabrication posture).  
- Tuning recovery speed deferred to magnitude mechanics (EWMA α, severity scaling).

## Must never happen (red lines)

- Upward movement permitted inside a failure window.  
- Downward movement forbidden inside a failure window (downward always allowed post-failure).  
- Automatic upward jump or reset after failure window (recovery must be earned via permitted movement).  
- Severity flipping any permission gate (e.g. high severity suppressing upward in partial).  
- Multi-cycle suppression by default (single-cycle window only unless new ADR).

## Tests required (high-level deterministic assertions)

- Failure → next cycle: downward permitted, upward forbidden (even if success outcome).  
- Failure → cycle after next: upward permitted if success/partial occurs.  
- Success → upward permitted unless inside failure window.  
- Partial → both directions permitted regardless of severity.  
- Rejected/deferred → no movement (assert == previous value).  
- Deterministic replay: failure → success → failure window blocks upward on the success cycle; next cycle allows upward on another success.  
- Severity=1.0 on partial/success → downward amplified, but upward still permitted if not blocked.
