# ADR-034: CI Workflow Foundational Contract

**Status**  
LOCKED (semantic invariant for v0.2.0 core)

## Objective

Define the authoritative contract, principles, and layered structure for the CI workflow in ECK, ensuring it verifies locked invariants without introducing external dependencies, network calls, flakiness, or behavioral assumptions into core testing.  

CI must serve as a guardian of deterministic semantics and remain last in the v0.2.0 roadmap (per ADR-020) to follow — not lead — stable design.

This ADR is scoped to the foundational "what" of A5 in the v0.2.0 roadmap (ADR-020). It builds on emergent architectural properties (especially Properties 4, 5, 11, 12), §19 red lines (no dependency creep, core stdlib-only), and all prior locked ADRs without reopening semantics.

## Decisions

1. **Two-Layer CI Structure**  
   - **Deterministic Core Layer** (mandatory, blocking)  
     - Runs on every push/PR to main.  
     - 100% stdlib/pytest-based, no real LLM calls, no optional extras, no network/external services.  
     - Verifies invariants: prompt equivalence (toggle/disabled/removed), fallback identity, no authority leakage (structured control fields ignored), policy irreversibility, critic pessimistic failure, memory retrieval bit-for-bit identity, queue deterministic ordering, confidence trajectory replay, etc.  
     - Goals: fast (< 3 min), zero flakiness, reproducible offline, enables confident merges.  

   - **Capability/Optional Layer** (non-blocking, advisory)  
     - Runs conditionally (e.g., after core passes or on main).  
     - Includes extras matrix (embeddings on/off), local LLM smoke tests (if env allows), integration checks.  
     - Allowed to be slower/flakier; failures → warning/Slack/artifact upload but do not block merge/release.  
     - Goals: validate real-world extras behavior and end-to-end realism without risking core invariants.

2. **Core Layer Principles**  
   - Must run in a completely isolated, deterministic environment (no internet, no external APIs, no real models).  
   - All tests must be offline-reproducible on any developer machine with only Python + pytest + stdlib.  
   - Coverage enforcement: fail build if branch coverage < 95% on kernel paths (configurable via new ADR only).  
   - Artifacts: coverage reports, pytest JUnit XML, logs uploaded for review.

3. **Capability Layer Constraints**  
   - Allowed to use optional extras and local LLM stubs/smoke tests.  
   - Failures must be non-blocking: report via artifacts, notifications, or badges — never block PR merge or release.  
   - Must skip gracefully if optional dependencies are missing (no crash).

## Rationale & Architectural Alignment

- Deterministic core layer protects microkernel verifiability path (Property 12) and TCB containment (Property 1) by isolating formal-like checks.  
- Capability layer allows evolutionary validation of optional features (Property 13 decoupling) without contaminating core guarantees.  
- Two-layer separation enforces observability before enforcement (Property 5) and atomic fallback (Property 4) in CI itself.  
- Placing CI last (ADR-020) ensures it verifies — not influences — stable semantics.  
- No network/external deps in core preserves refusal-over-fabrication posture and minimalism.

## Must Never Happen (Red Lines)

- Network calls, real LLM invocations, or external services in deterministic core layer.  
- Non-stdlib runtime dependencies required for core CI.  
- Capability-layer flakiness or failures blocking merges/releases.  
- CI introducing assumptions that contradict locked invariants (e.g., retry logic, timeouts affecting deterministic replay).  
- Coverage thresholds ignored or lowered without new ADR.  
- Reopening of prior ADRs or §19 red lines via CI configuration.

## Tests Required / Verification Surface (High-Level)

- Core layer must pass 100% deterministic invariant assertions from prior ADRs (memory toggle equivalence, critic pessimistic failure, policy upgrade irreversibility, queue determinism, confidence trajectory replay, ADR-033 guardrails).  
- Adversarial structured field tests (from ADR-033) integrated into core.  
- Fallback identity: extras-missing run produces identical results to core-only.  
- Coverage enforcement: core layer fails if branch coverage < 95% on kernel paths.  
- Capability layer: successful extras-enabled run + local LLM smoke (if present) → artifacts uploaded.
