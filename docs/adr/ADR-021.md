# ADR-021: Rolling Confidence Update Cadence

**Status**  
Locked (semantic invariant for v0.2.0 core)

## Decision

Confidence shall be updated **exactly once per full task cycle**, immediately after critic evaluation (i.e., after `critic.evaluate()` has produced a success/failure/partial outcome and severity), and **before** the next prediction/generation phase begins.

## Core rules (hard invariants for v0.2.0)

- Exactly one update per cycle that produces a critic outcome.
- If no critic outcome exists for a cycle (e.g. immediate deferral before critic, early exit, or any path that skips evaluation), confidence **MUST NOT** update and remains unchanged.
- The v0.2.0 core assumes exactly one critic outcome per task cycle. Any future architecture introducing multiple critic calls per cycle, sub-critics, retries with intermediate evaluation, or parallelism requires a new ADR and explicit re-evaluation of this invariant.
- No mid-cycle updates, no speculative/anticipatory updates, no batch/retrospective updates over multiple cycles (at least not in v0.2.0 core).

## Rationale

- Matches epistemic meaning: revise trust after observing outcome.
- 1:1 explainability between critic events and signal changes.
- Prevents leakage into prediction/execution phases.
- Enables monotonicity/asymmetry by construction (single post-failure window).
- Aligns with step() structure, DriftMonitor per-task semantics, and roadmap layering (semantics before wiring, confidence downstream of facts).

## Consequences

### Positive

- Clear causal logs (“dropped to 0.38 after severity=0.9 failure on task X”).
- Fully deterministic, reproducible trajectories from fixed outcome sequences.
- Natural fit for streak/drift tracking.

### Trade-offs

- One-cycle latency on reaction (acceptable given episodic design).
- No support for mid-cycle or multi-critic signals without future ADR.

## Must never happen (red lines)

- Confidence update before critic evaluation.
- Multiple updates per task cycle.
- Update during prediction/generation phases (violates layering).
- Update triggered by absence of critic outcome (phantom movement violates epistemic integrity).
- Any assumption of multiple critic calls per cycle baked into v0.2.0 logic.

## Tests required (high-level deterministic assertions)

- Given sequence of N critic outcomes → exactly N updates occur.
- Cycle with no critic outcome → confidence remains unchanged (assert == previous value).
- After first critic evaluation → first update occurs (no longer 0.5 unless outcome justifies it).
- Deterministic replay of outcomes [S, S, F, S] → exactly four updates, third ≤ second (placeholder for asymmetry).
- Confidence logged/inspectable exactly once per update, tied to critic result.
