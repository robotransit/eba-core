# ADR-032: Optional Embeddings + Cosine Integration

**Status**  
Locked (semantic invariant for v0.2.0 core)

## Objective

Define the precise integration contract, configuration surface, and fallback strategy for the optional embeddings + cosine similarity upgrade in ECK, ensuring the feature remains strictly additive, fully disable-able, with no behavioral or prompt divergence from ADR-031 fallback.

This ADR is strictly scoped to A3 step 2 in the decomposition document and builds directly on the API contract locked in ADR-031 without reopening prior decisions (A1, A2, or ADR-031), introducing new authority surfaces, or coupling similarity to confidence, policy modes, breadth, or gating.

## Decisions

1. **Dependency Declaration**  
   The embeddings + cosine functionality is provided exclusively via an optional extras group (`eck[embeddings]`) in `pyproject.toml`.  
   It depends on a lightweight, version-pinned embedding library (e.g., sentence-transformers or equivalent) and is never part of the core package or default installation.

2. **Configuration Surface**  
   A single boolean flag is added to `ECKConfig`:  
   `enable_embeddings: bool = False` (default off, even if the extras group is installed).  
   When `False` (or when the extras are not installed), the system uses only the stdlib-only fallback path defined in ADR-031.

3. **Integration Point**  
   When both `enable_embeddings=True` and the extras are installed:  
   - The optional embedding model is loaded once at `ECKAgent` construction.  
   - `retrieve_similar` and `retrieve_scored` use cosine similarity on embeddings for candidate ranking.  
   - The `query_embedding` parameter (if supplied) is used; otherwise a fresh embedding of the current prediction context is computed.  
   - Returned items (or scored tuples) are still passed through the exact same memory context formatting as the core fallback, preserving byte-for-byte prompt equivalence when fallback is triggered.

4. **Fallback Strategy**  
   When the extras are missing, disabled, or the embedding model fails to load:  
   - Both retrieval methods immediately and atomically fall back to the stdlib-only heuristic path from ADR-031 (no partial state or partial execution is possible).  
   - No exception is raised to the agent loop.  
   - Prompt form, ordering stability, and all observable behavior remain identical to the core path.

## Invariants

- The embeddings feature is strictly optional: `enable_embeddings=False` (or missing extras) produces exactly the same behavior and prompt output as the core stdlib-only path in ADR-031 (no drift).  
- Core package and default installation remain 100% stdlib-only; no optional code is imported or executed unless explicitly enabled.  
- Optional dependency failure (missing extras, import error, model load failure) results in graceful, silent, immediate, and atomic fallback with zero impact on agent execution, policy, confidence, or gating.  
- Similarity scoring and ordering (when enabled) remain advisory only: returned items feed into memory context formatting without gaining behavioral authority (prediction owns generation).  
- Enabling embeddings does not alter the deterministic tie-breaking rules (reverse-chronological among equals) defined in ADR-031.  
- No coupling exists between embeddings/cosine and confidence scoring, task breadth estimation, policy mode transitions, or execution gating.  
- All prior contracts (ADR-026–031, A1 semantics, §19 red lines) remain closed and unaffected.  
- The `query_embedding` parameter continues to be ignored in the fallback path (per ADR-031).  
- Partial initialization of the embeddings model (or any partial-load state) must trigger immediate atomic fallback with no undefined or semi-enabled retrieval state.  
- Candidate metadata and formatting integrity are preserved exactly even when embeddings/cosine ranking is used, ensuring tests relying on ADR-031 prompt equivalence remain valid.

## Must Never Happen

- Optional embeddings/cosine becoming required for core functionality or default installation.  
- Core package acquiring a non-stdlib dependency (direct or transitive).  
- Optional dependency failure causing any exception, HALT, policy change, or behavioral divergence from the ADR-031 core path.  
- Prompt drift or ordering instability when toggling `enable_embeddings` or installing/uninstalling the extras.  
- Embeddings/cosine influencing confidence values, breadth decisions, policy modes, or gating in any way.  
- Hidden or unconditional import of optional code in the core retrieval path.  
- Reopening or reinterpretation of ADR-031 API contract, A2 memory wiring, A1 semantics, or §19 red lines.
