# ADR-046: Mechanical Enforcement Layer for v0.4.0

## Status
Partially Adopted — mypy and CodeQL implemented; icontract deferred

## Context
With v0.3.0 complete and the core invariants from ADR-020–ADR-045 now locked in code, we need systematic mechanical enforcement to prevent regression and make invariant violations loud and visible.

The mechanical enforcement layer consists of three tools:
- mypy (static type checking)
- CodeQL (static analysis and security scanning)
- icontract (runtime contract enforcement — deferred, see below)

This ADR defines exactly which rules and targets each tool will enforce.

## Decision

### 1. mypy Configuration
We will **not** enable the full `--strict` bundle.

**Adopted flags:**
- `--disallow-untyped-defs`
- `--disallow-any-generics`
- `--warn-return-any`
- `--strict-equality`
- `--no-implicit-reexport`
- `--warn-unused-ignores`
- `--no-implicit-optional`

**Explicitly excluded:**
- `--disallow-any-explicit` — ECK deliberately uses `Any` in controlled places (e.g. `proposed_action: Any` in PolicyGate and some telemetry payloads)
- `--disallow-subclassing-any` — adds unnecessary friction with optional third-party dependencies
- Full `--strict` bundle — replaced by the explicit curated list above

All adopted mypy flags are blocking in CI. The codebase is clean — zero violations across 21 source files.

### 2. CodeQL Configuration
- `python/security-extended` — enabled and blocking in CI from day one
- `python/quality` — deferred; the standalone `quality` pack name is not directly accessible via the `queries` parameter in `github/codeql-action/init@v3`. To be revisited when the correct pack reference is confirmed.

### 3. Enforcement Matrix

| Surface | Static Enforcement | Runtime Enforcement |
|---|---|---|
| PolicyGate contract | mypy under the ADR-046 curated profile (evaluate() callable surface, static structural Protocol conformance via typing.Protocol, optional telemetry kwargs: trace_id, step_id, deterministic_nonce) | None |
| ProposedAction schema surface | mypy under the ADR-046 curated profile | Deferred — see icontract section |
| authorize_and_perform authority boundary (INV3, INV6) | None | Deferred — see icontract section |
| Confidence update invariants | None | Deferred — see icontract section |
| Telemetry envelope validity | mypy under the ADR-046 curated profile | Existing validate_event() |

### 4. icontract — Deferred

icontract was introduced incrementally across three surfaces and subsequently reverted in full. The reasons:

**authorize_and_perform:** icontract decorators duplicated existing `AssertionError` raises for INV3 and INV6 and changed the observable exception type from `AssertionError` to `ViolationError` without adding enforcement value. The existing explicit raises are sufficient and correct.

**ConfidenceSignal.update():** icontract decorators on instance methods broke `self` method resolution at runtime — private helper methods (`_compute_raw_delta`, `_derive_base_and_effective_class`, `_apply_gated_clamp`) became unreachable, producing `AttributeError` at runtime. This is a known incompatibility between icontract decorator wrapping and Python's method resolution in certain class configurations.

**ProposedAction.__post_init__():** icontract contracts on `__post_init__` fired at construction time, preventing tests from deliberately constructing invalid `ProposedAction` instances to exercise refusal paths in `authorize_and_perform`. The admissibility check belongs in `authorize_and_perform`, not in the type constructor. Additionally the callable check on `parameters.values()` fired before the `isinstance(parameters, dict)` guard, causing `AttributeError` on non-dict inputs.

**Conclusion:** The existing `ValueError` and `AssertionError` raises already enforce all invariants explicitly, with named messages, before any mutation occurs. icontract adds value when invariants are implicit or enforced only by convention — that is not the current state of the ECK codebase. icontract will be reconsidered when genuinely implicit invariants emerge that are not already covered by explicit raises.

## Rationale
- mypy strict profile gives strong static type coverage without conflicting with deliberate `Any` usage.
- CodeQL `security-extended` is prioritized because the kernel sits at a sensitive execution boundary.
- icontract is deferred — the existing explicit raises are the enforcement layer and they are sufficient.

## Consequences
**Positive:**
- mypy blocking in CI — violations are loud and caught before merge
- CodeQL security scanning — blocking on security findings
- No duplication of existing validation (`validate_event()`)
- Codebase is clean: zero mypy violations, zero CodeQL security findings

**Negative:**
- icontract runtime enforcement deferred
- CodeQL quality suite deferred pending correct pack name resolution

**Mitigation:**
- The existing `ValueError` and `AssertionError` raises in the codebase serve as the runtime enforcement layer for the most critical invariants.
- icontract will be reintroduced in a future release when the correct surfaces and patterns are identified.
